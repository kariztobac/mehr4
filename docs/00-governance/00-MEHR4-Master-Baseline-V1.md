## 1. هدف سند و اصول غیرقابل تغییر

این سند مرجع واحد تصمیم‌گیری فنی، محصولی، امنیتی و اجرایی پروژه است.  
تمام اسناد قبلی (Vision، Roadmap، Architecture، Master Execution Plan، پروتکل کنسرسیوم و جریان کاربر) در این سند ادغام و موارد تکراری حذف شده‌اند.

### اصول بنیادین (غیرقابل مذاکره)
- Reality > Claim
- Accuracy > Confidence
- Evidence + Provenance برای هر ادعای حقوقی
- Human-in-the-loop برای خروجی‌های حساس
- Security by Design، Audit، Backup، Versioning و Rollback از روز اول
- **قانون الزامی آینده‌نگری**: هر قابلیت آینده باید از امروز در معماری، نقشه و ساختار جا داشته باشد، اما غیرفعال یا فقط Placeholder باشد.
- امروز ساده می‌سازیم؛ هسته را طوری طراحی می‌کنیم که بدون بازنویسی بنیادی مقیاس‌پذیر شود.

#### اصل استقلال ماژولار (Airplane Principle) — غیرقابل مذاکره
سیستم نهایی باید مانند یک هواپیما طراحی شود:
- هر بخش (ماژول، Adapter، لایه، سرویس) یک «قطعه» کاملاً مستقل است.
- تعویض یا تغییر یک قطعه (حتی تعویض کامل یک موتور) نباید باعث نیاز به بازطراحی یا خرابی سایر بخش‌ها شود.
- وابستگی‌ها فقط از طریق Interfaceهای پایدار و مشخص برقرار می‌شوند.
- هیچ ماژولی حق ندارد مستقیماً به جزئیات داخلی ماژول دیگر وابسته باشد.
- این اصل بر تمام تصمیمات معماری اولویت دارد.

## 2. چشم‌انداز و مأموریت

**چشم‌انداز:** ساخت پلتفرم حقوقی هوشمند کشور (ایران) که هم روی وب و هم روی گوشی (PWA) کار کند، از MVP کوچک و کم‌هزینه شروع شود و بدون بازنویسی هسته به سامانه خدمات قضایی مقیاس‌پذیر ارتقا یابد.

**مأموریت فعلی (فاز تمرکز):**  
اجرای کامل و قابل تجربه عملی **پروتکل متیس (Metis Consortium Protocol)** به‌عنوان هسته اصلی تحلیل پرونده.  
کاربر عادی باید بتواند تمام جریان تشکیل پرونده، پرسش‌وپاسخ تخصصی، ماتریس ادله، تحلیل چندلایه، شبیه‌سازی دفاع طرف مقابل و خروجی قابل اقدام را دقیقاً مانند یک اتاق فکر حقوقی حرفه‌ای تجربه کند.

## 4. معماری فاز اولیه (Modular Monolith)

**فناوری پایه:**  
Next.js + React + TypeScript + Node.js + PostgreSQL  

**اصول معماری:**
- **Airplane Principle**: هر ماژول قطعه مستقل است (تعویض یک بخش بدون تأثیر روی بقیه)
- Modular Monolith با مرزبندی بسیار سخت‌گیرانه (قابل تبدیل آسان به Microservices در آینده)
- PWA-First (قابل نصب واقعی روی گوشی Android/iOS)
- RTL کامل + Responsive
- تمام Interfaceهای آینده از امروز تعریف می‌شوند ولی غیرفعال
- وابستگی فقط از طریق Interface پایدار — هیچ وابستگی مستقیم داخلی مجاز نیست

### لایه‌های رزرو شده از روز اول (غیرفعال یا Placeholder)
- Auth / Consent / RBAC
- Case Module (هسته فعال)
- Document + Storage Interface
- OCR Interface
- AI Gateway + Provider Adapter (فعلاً تک‌مدل)
- Multi-LLM Orchestration (ساختار نهایی، غیرفعال)
- RAG / Retrieval / Knowledge Base
- Evidence & Provenance
- Human Review (Lawyer Review)
- Audit / QA / Logging
- Notification / Payment / Official Integrations (عدالت ایران و غیره)
- Feature Flags
- Observability

### جریان اصلی کاربر عادی (اولویت فعلی)
1. تشکیل پرونده جدید  
2. پرونده‌های در جریان  
3. پرونده‌های مختومه  
4. همه پرونده‌های شخص  
5. وکلای مرتبط (Placeholder)  

**درون تشکیل پرونده و پرونده در جریان (تمرکز متیس):**
- شرح پرونده: فیلد آزاد با ظرفیت بسیار بالا (حداقل ۱۰۰٬۰۰۰ نویسه) + سیستم اختیاری تقسیم به بخش‌های ساختاریافته (خط زمانی، طرفین و قراردادها، ادعاها، مکاتبات، بخش سفارشی)
- آپلود مدارک (گروهی یا تکی) + متادیتا + قابلیت هایلایت بخش‌های مهم
- پرسش‌های تکمیلی پویا (موتور متیس)
- مدارک و شواهد
- تحلیل و آنالیز کامل طبق پروتکل متیس (بر اساس کل حافظه پرونده)
- افزودن دلیل و مدرک
- پرسش و پاسخ تخصصی
- ارتباط با وکیل / انتخاب وکیل (Placeholder)
- خلاصه پرونده + ماتریس ادله + خروجی اجرایی

**قانون حیاتی تحلیل:**
هر پاسخ یا اقدام سیستم باید بر اساس بازبینی کامل دیتابیس پرونده (تمام بخش‌ها، سؤالات قبلی، رفع ابهامات، مدارک و تأثیر اثباتی آن‌ها، ماتریس ادله و تاریخچه) انجام شود. تحلیل ایزوله ممنوع است.

## 5. پروتکل متیس (Metis Consortium Protocol) — هسته اصلی فعلی

نام رسمی پروتکل از این پس: **متیس**

### اصول متیس
- اتاق فکر حقوقی چندلایه، دیالکتیکی، ضدتوهم، عمل‌گرا
- تمرکز انحصاری بر نظام حقوقی و قضایی جمهوری اسلامی ایران
- خروجی قابل استفاده در عمل (استراتژی، ریسک، خواسته، ماتریس ادله، شبیه‌سازی دفاع، برنامه اقدام)
- حافظه پویا و زنده پرونده (Case Memory Protocol)
- تفکیک اجباری Fact / Doubt / Missing
- ممنوعیت تحلیل ایزوله
- پروتکل ضدتوهم قوانین (برچسب [⚠️ نیازمند راستی‌آزمایی])
- سطوح تحلیل ۱ تا ۴ (پیش‌فرض سطح ۳)
- واحد حریف تمرینی (Devil’s Advocate)
- لایه ناظر عالی (سبک رئیس)
- طراحی برای اجرای حکم (نه فقط صدور رأی)

### موتور هشت‌مرحله‌ای (اجباری در سطح ۳ و ۴)
1. قفل کردن موضوع  
2. تفکیک Fact / Doubt / Missing  
3. ماتریس ادله  
4. نقشه خواسته‌ها و دفاعیات  
5. حمله طرف مقابل  
6. قضاوت احتمالی  
7. خروجی اجرایی  
8. Metadata و به‌روزرسانی حافظه پرونده
